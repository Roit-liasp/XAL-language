Глава 7. Модули

7.1 Module, import, use и pub

Большую программу удобно резать на куски. Один файл - один модуль.
В начале файла указываешь его имя:

  module(lib)

Чтобы воспользоваться чужим модулем, его импортируют по имени файла
без расширения:

  import "mod/lib";

Слово use пока ничего не делает - оно зарезервировано на будущее.
Можно писать строки вроде "use lib.answer;" - компилятор молча
пропустит их мимо.

Слово pub открывает имя наружу. Без него функция или переменная
видна только в своем файле:

  module(lib)
  pub let LV = 100;
  pub fn answer() { return 42; }
  let sekret = 1; # видно только здесь

А в главном файле после импорта можно писать просто LV и answer() -
короткие имена подхватятся сами. Полные тоже работают: lib.answer().

7.2 Где компилятор ищет модули

Строка в импорте - это путь к файлу. Расширение .xa можно не писать,
его допишут само. Папки просматриваются в таком порядке:

- папка, где лежит файл с импортом;
- папка, где лежит главный файл;
- текущая папка;
- папка из переменной окружения XAL_LIB или /lib/xal, если ее нет.

Если модуль не нашелся нигде - компиляция остановится с понятной
ошибкой. Один и тот же модуль, импортированный дважды, подключится
только один раз - по второму разу ничего не произойдет.

7.3 Как складываются имена

Правило одно: открытое имя складывается из имени модуля, точки
и собственного имени. Pub функция answer в модуле lib становится
lib.answer. Если module() в файле не указан, имя остается как есть.

Когда ты пишешь короткое имя, компилятор ищет его в таком порядке:

- локальная переменная с этим именем;
- открытое имя текущего модуля;
- любое открытое имя с таким хвостом после точки;
- иначе - обычное глобальное имя.

Практический вывод: в библиотеках всегда пиши module() в начале
и открывай наружу только нужное через pub. Тогда имена не пересекутся
и чужой файл не сломает твои переменные.
