Глава 8. Встроенные функции

Встроенные функции здесь называют нативными. Их не надо объявлять
или импортировать - просто вызывай. Ниже все они, разложенные по полкам.
В скобках - аргументы, дальше - что функция возвращает.

8.1 Печать и ввод

- print(a, b, ...) - печатает все аргументы через пробел и перевод
  строки в конце. Возвращает 0.
- puts(a, b, ...) - печатает все сразу, без пробелов и без перевода
  строки. Возвращает 0.
- input() - читает строку из консоли без перевода строки. На конце
  файла взводит флаг eof.
- eof() - возвращает 1, если ввод уже уперся в конец файла.
- read(fd, сколько) - читает кусок из дескриптора. По умолчанию
  fd 0 (консоль) и 4096 байт. Возвращает строку.
- write(fd, s) - пишет строку в дескриптор. Возвращает число
  записанных байт.
- open(путь, режим) - открывает файл. Режим "r" чтение, "w" запись
  с очисткой, "a" дозапись. Возвращает дескриптор или отрицательное.
- close(fd) - закрывает дескриптор.

8.2 Строки

- len(x) - длина строки или списка. Без аргументов даст 0.
- str(x) - превратит в строку.
- int(x) - превратит в число.
- split(s, разд) - режет строку по разделителю, по умолчанию по
  пробелу. Возвращает список.
- join(список, разд) - склеивает список в строку через разделитель,
  по умолчанию пробел. Не список даст пустую строку.
- substr(s, старт, длина) - кусок строки. Границы подрезаются сами.
- find(s, под) - позиция подстроки или -1.
- eq(a, b) - 1, если строки равны как текст.
- ord(s, i) - код символа на позиции i или -1.
- chr(n) - строка из одного символа с этим кодом.
- trim(s) - убирает пробелы и переводы строк с обоих краев.
- upper(s), lower(s) - верхний и нижний регистр, только английские буквы.
- replace(s, что, чем) - заменяет все вхождения. Пустое "что" ничего не меняет.
- startswith(s, начало), endswith(s, конец) - проверки краев, 1 или 0.
- repeat(s, n) - повторяет строку n раз.

8.3 Списки

- sort(список) - возвращает НОВЫЙ отсортированный список, старый не трогает. Сортирует как строки. Не список вернет как есть.
- copy(список) - поверхностная копия списка. Не список даст [].
- insert(список, куда, что) - вставляет на место, меняя сам список. Возвращает тот же список.
- remove(список, куда) - удаляет элемент, меняя сам список.

8.4 Числа и время

- abs(x) - модуль числа.
- min(a, b), max(a, b) - меньшее и большее.
- now() - текущее время в секундах.
- sleep(ms) - пауза в миллисекундах. Возвращает 0.

8.5 Файлы и папки

- exists(путь) - 1, если путь существует.
- isdir(путь) - 1, если это папка.
- isexec(путь) - 1, если это запускаемый файл.
- mtime(путь) - время изменения в секундах или -1.
- mkdirp(путь) - создает папку вместе с родителями. 0 значит получилось.
- unlink(путь) - удаляет файл. 0 значит получилось.
- rename(старый, новый) - переименовывает. 0 значит получилось.
- readdir(папка) - список имен в папке. По умолчанию текущая.
- readfile(путь) - весь файл одной строкой или "" если не читается.
- writefile(путь, данные) - записывает строку в файл. Возвращает число байт или -1.

8.6 Окружение и пути

- getenv(ключ) - значение переменной окружения или "".
- setenv(ключ, значение) - устанавливает переменную.
- getcwd() - текущая папка.
- chdir(путь) - переходит в папку. 0 значит получилось.
- which(имя) - ищет программу в PATH. Возвращает полный путь или пустую строку.
- argv(i) - i-тый аргумент командной строки, argv(0) это сама программа.
- argc() - сколько всего аргументов.

8.7 Процессы

- exec(список) - запускает программу и ждет конца. Первый элемент - команда, остальные - аргументы. Возвращает код возврата. Вместо списка можно строку - тогда это команда без аргументов. Имя без косой черты ищется в PATH.
- spawn(список) - запускает и не ждет. Возвращает номер процесса.
- wait(pid) - ждет процесс и возвращает его код.
- waitpid(pid, не_ждать) - то же, но с флагом: 1 - не ждать, вернуть -2, если процесс еще работает. -1 - нет такого процесса (или в системе этого не умеют).
- getpid() - номер текущего процесса, -1 если процессов нет.
- kill(pid, сигнал) - послать сигнал (по умолчанию 15, SIGTERM). 0 получилось, -1 нет.
- fork() - копия процесса: в потомке 0, в родителе номер потомка, -1 если fork в системе нет (Windows, голое железо, ядра без fork). Сразу после fork потомок обязан вызвать execv: две живые копии виртуальной машины - это поломка, а не многозадачность.
- pipe() - канал: список [чтение, запись]. Не вышло - пустой список.
- dup2(старый, новый) - подменить дескриптор. 0 получилось, -1 нет.
- signal(сигнал, режим) - 0 (XOS_SIG_DFL, по умолчанию) или 1 (XOS_SIG_IGN, игнорировать). -1, если система сигналов не умеет.
- sys(команда) - выполняет строку через shell. Возвращает код.
- execv(список) - заменяет текущий процесс новой программой. При успехе назад не возвращается.
- exit(код) - завершает программу с этим кодом. Если программа запущена вложенно (run_xb), завершается только она, а не вся машина.

8.8 Терминал

- rawmode(вкл) - включает или выключает сырой режим терминала. По умолчанию включает.
- getkey() - читает один байт с консоли или -1.
- termsize() - список из двух чисел: ширина и высота терминала.
- isatty(fd) - 1, если дескриптор это терминал. По умолчанию fd 0.

8.9 Потоки и каналы

- spawn_thread(функция, аргументы) - запускает функцию в новом потоке. Функцию называют строкой с именем или номером. Аргументы - список. Возвращает номер потока или -1. Если функции нет - ругнется в консоль и вернет -1.
- join_thread(id) - ждет поток и возвращает то, что вернула функция.
- thread_id() - номер текущего потока.
- thread_cpu(), set_affinity() - заглушки: 0 и -1.
- nproc(), cpu_count() - сколько процессоров видно. Обе дают одно и то же.
- chan_new() - новый канал, возвращает его номер.
- chan_send(канал, значение) - кладет значение в канал. 0 успех.
- chan_recv(канал) - забирает значение, если пусто - ждет.
- chan_tryrecv(канал) - забирает без ожидания, если пусто - даст 0.
- chan_close(канал) - закрывает канал.
- parallel_map(функция, список) - применяет функцию к каждому
  элементу, работая в несколько потоков. Возвращает новый список.

8.10 Память и сборщик мусора

Строки и списки живут под присмотром сборщика мусора: память освобождается
сама, когда значения становятся недоступны. Вмешиваться обычно не надо,
но три ручки есть:

- gc_collect() - принудительно собрать мусор прямо сейчас.
- gc_count() - сколько сборок уже было.
- gc_stat() - список из трех чисел: включен ли сборщик, сколько сборок было, сколько байт сейчас занято.

8.11 Запуск образов и возможности системы

- run_xb(путь, аргументы) - запускает .xb образ и ждет его конца.
  Аргументы - список строк, первый элемент - имя программы (как
  в exec); не дашь - будет один аргумент, сам путь. Возвращает код
  возврата (0..255), -1 если запустить не удалось, 126 если образ
  требует того, чего эта система не умеет.
  Образ запускается вложенно, в той же виртуальной машине: так это
  работает и под Unix, и внутри ядра без fork/exec. Если вложенный
  запуск невозможен (кончилась глубина, запрещен хостом), а процессы
  создавать можно - xvm передаст образ внешнему интерпретатору:
  своему argv[0] или тому, что лежит в XAL_VM.
  Глубина вложенности ограничена (XVM_NEST_MAX, по умолчанию 8).
- caps() - список возможностей, которые у системы есть.
- has_cap(имя) - 1, если возможность есть. Имена: io, fs, dir, env,
  cwd, proc, kill, fork, pipe, signal, term, threads, time, xb.

xvm встраивают куда угодно: в Unix-процесс, в ядро без fork/exec,
в голое железо. У каждой нативной функции есть список нужных ей
возможностей; перед запуском xvm смотрит, чего требует образ, и если
чего-то нет - не запускает его вовсе (код 126 и понятное сообщение),
а не падает посередине. Проверить образ без запуска можно так:

    xvm --caps program.xb

Фоном образ запускается средствами процессов: `fork()`, а в потомке -
`run_xb()` и `exit()` (сразу после fork потомок должен запустить образ и
выйти: две живые копии виртуальной машины - это поломка):

    let pid = fork();
    if pid == 0 {
        exit(run_xb("/bin/util.xb", ["util", "arg"]));
    }
    let code = wait(pid);

Ядро, встроившее xvm, объявляет свои возможности само: либо
сборкой (-DXVM_CAPS_DEFAULT=...), либо в рантайме - xvm_caps_disable()
для того, чего в нём точно нет. Смягчить поведение можно переменной
XVM_CAPS_STRICT=0: тогда вместо отказа будет предупреждение, а
недоступные функции вернут -1.
